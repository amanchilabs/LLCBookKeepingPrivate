## Shared state and interaction requirements

| State / dialog | Current evidence | Canonical requirement |
|---|---|---|
| Initial setup / no business | First-launch branch in `BookkeepingApp` opens `BusinessSetupScreen` | Welcome and setup steps; preserve progress between steps in memory; no persistence until explicit create. If the app is interrupted, state behavior must be defined before implementation. |
| Loading / encrypted store unavailable | `BookkeepingApp` loading and load-error branches; open recovery or retry | Keep records untouched; explain retry and recovery; never claim a biometric lock screen exists. |
| Empty dashboard / no accounts | Dashboard empty helper text | Explain the first safe action; opening balance is distinct from contribution and income. |
| Empty transaction list / no filter results | `TransactionsScreen` no-results message | Distinguish no saved records from no filter matches. Offer clear filters and add transaction. |
| Invalid money/date/category/split | FormError and domain validators | Retain entered values; show exact issue. Amounts use fixed-precision parser; split lines must sum exactly; do not post partially. |
| Ownership total invalid | `parseOwnershipPercent`, replace/create validation | Show current total and required 100%; block save; do not silently rebalance or allocate profits. |
| No account for activity | Transaction/member/loan forms validate account availability | Link directly to create an account. Do not silently select an unrelated account or post an unexplained balancing line. |
| Posted transaction correction | Existing `correctCashTransaction` creates reversal plus replacement | Preview original, reversal and replacement amounts/accounts/date effects; confirm; preserve all three in history. No edit/delete. |
| Obligation vs payment | Current source explicitly says obligation creates no journal/cash event | Label both states and cash effect; no payment means no cash-basis expense. |
| Loan commitment vs advance | Loan agreement and activity are distinct records | Commitment amount is ceiling only; only advances create principal/cash/liability; repayments split principal and paid interest. |
| Reconciliation active / difference | Current source tracks statement difference and cleared items | Show outstanding/unmatched activity, statement ending amount and difference; do not create adjustment entries automatically. |
| Report invalid range / no entries / export failure | `ReportsScreen` validates dates and reports errors | Keep chosen dates; show zero vs unavailable distinctly; export failure must not imply file saved/shared. |
| Period closed | Settings records close/reopen events | Explain blocked posting date and reason; reopen only through explicit audited action. |
| Backup restore confirmation / wrong password / invalid file | Existing native proof UI and backup modules | Keep the current recovery controls. Confirm target and overwrite effect; reject invalid/tampered/wrong-key data without partial restore; never claim cloud backup. |
| Unsaved form dismissal | Not consistently represented in mockups | Ask before discarding a dirty form; provide Cancel and Discard. Avoid ambiguous back behavior on Android. |

## Source map and domain boundaries

- Shell and current routes: `apps/mobile/bookkeeping/BookkeepingApp.tsx`; screens under `apps/mobile/bookkeeping/`.
- Profile/member setup: `BusinessSetupScreen.tsx`, `packages/domain/src/bookkeeping.ts`, `createBusiness` in `packages/storage-native/src/bookkeeping-service.ts`.
- Transactions/corrections: `TransactionsScreen.tsx`, `packages/domain/src/money.ts`, `packages/domain/src/journal.ts`, `recordCashTransaction`, `recordSplitCashTransaction`, `recordTransfer`, and `correctCashTransaction` in `bookkeeping-service.ts` / `bookkeeping-store.ts`.
- Accounts/reconciliation: `AccountsScreen.tsx` and account/reconciliation service/store functions. Balances are derived from persisted journal lines; reconciliation is matching metadata and does not itself alter balances.
- Capital, member history, guaranteed payments: `MembersScreen.tsx`; member/capital/payment service and store functions; domain bookkeeping records. Ownership history, capital activity, obligations, and payment cash events are distinct.
- Loans: `LoansScreen.tsx`, `packages/domain/src/loan-interest.ts`, loan agreement/advance/repayment service and store functions.
- Reports: `ReportsScreen.tsx`, `report-exports.ts`, `report-pdf.ts`, and read/report service functions in `bookkeeping-service.ts`.
- Settings and supporting flows: `SettingsScreen.tsx`, `WorkspacesSection.tsx`, `RemindersSection.tsx`, recurring/import panels, `App.tsx` native proof entry.
- Persistence: `packages/storage-native/src/bookkeeping-service.ts` and `bookkeeping-store.ts` over the encrypted local store. No remote sync dependency is implied.
