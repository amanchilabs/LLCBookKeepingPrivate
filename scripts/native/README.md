# PR #1 native certification helpers

Use only a dedicated **fresh synthetic** target. `security.yaml` performs generation-replacing restore proofs; never run it against existing books. Its Get started precondition prevents starting from a populated bookkeeping workspace. Physical-device, real-data, production-signing and store certification are separate gates.

Build with the pinned Node/lockfile. Use `scripts/build-ios-simulator.sh` with the app development team and a dedicated simulator. Build Android Debug for arm64 with JDK17. Start Metro on a free local port (this run:8089), and use adb reverse on the selected emulator only. Open the development client with `__expo_url`, `__expo_disable_fab=1`, `__expo_disable_auto_launch=1`, and `__expo_disable_onboarding=1` so development overlays do not intercept controls. On iOS, accept any OS Open confirmation before starting. These flags affect development tools, not encryption or authentication.

1. Run `security.yaml`, then Return to books. It verifies SQLCipher/SecureStore, wrong-key rejection, in-memory backup rejection/recovery and ten exception boundaries before bookkeeping records exist.
2. Reuse `docs/development/consolidation-20261103/flows/onboarding.yaml` and `accounting.yaml`. The latter is now exercised by this certification follow-up; its old historical README describes the earlier checkpoint only. They create $1,000 opening, $250 income, $50 expense replaced with $75, and $100 capital: cash $1,275 and trial-balance totals $1,350.
3. For iOS, adapt these input fixtures with `python3 scripts/native/ios-flow.py INPUT OUTPUT FOOTER` (use `"Storage and recovery tools"` for onboarding and `Dashboard` for bookkeeping). The iOS tree exposes both label and input, and single-line inputs use the native Return key to submit/blur instead of the unsupported standard keyboard-dismiss action. The adapter targets the input above that pinned footer and also uses bounded swipes inside the scroll pane; default full-screen swipes can activate the pinned recovery footer. This changes selectors/gestures, not financial expectations.
4. Run `filters-navigation.yaml`: description search finds 1 of 5 persisted cash records; Expense filter shows original+replacement (2 of 5). The reversal is a separate reversal-kind record, retained in All activity. Capital is tracked separately from this cash transaction list. Navigate Accounts and Settings under More.
5. Export Trial Balance CSV/PDF using the system share sheets without selecting a destination. Verify captured files with `python3 docs/development/consolidation-20261103/validate-native-export.py CSV PDF` (requires pdftotext). Values must match exactly.
6. Force-stop/terminate and relaunch with the same development URL; reuse the existing persistence fixture to verify cash, member and contribution. Do not clear data. iOS startup re-reads the same Keychain-protected key.

Native flow logs/binaries/device data remain local regenerable QA assets; acceptance results and source/artifact identities are summarized in docs/development/PR1-CERTIFICATION.md. These helpers do not certify process-kill during restore, power loss, OS backup transfer, physical hardware Keychain/Keystore, or a production bookkeeping backup format.

The separately opted-in SQLCipher-negative check uses `LLCB_SECURITY_NEGATIVE_SQLITE=1` for Android prebuild/build only. Keep the positive QA APK, hash all encrypted database files after force-stop, install the negative APK without clearing data, run `sqlcipher-negative.yaml`, and compare every file/hash. Restore the positive APK and verify persistence. Regenerate Android without the negative environment flag afterward. Never use a production build profile for this fixture; the existing policy rejects that combination. Current negative test preserved all five database files byte-for-byte, and the restored positive build retained $1,275 and the $100 contribution.
